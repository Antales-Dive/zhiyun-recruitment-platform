# 智聘云开发蓝图：需求与验收标准

## 1. 需求确认

### 1.1 问题与目标

`DECIDED` 当前目标不是制作界面演示，而是建立可持续开发和生产运营的企业招聘平台。HR 应能从岗位创建开始，经简历导入、解析、匹配、人工复核、问卷、排期和面试，形成可追踪的招聘流程；管理员可管理制度知识和审计；候选人通过受控链接参与问卷和文字面试。

### 1.2 参与者

| 参与者 | 核心权限 |
| --- | --- |
| `ADMIN` | 用户与角色、组织配置、Provider 配置状态、知识发布、审计查看 |
| `HR` | 岗位、候选人、分析、问卷、排期、通知、人工决策 |
| `INTERVIEWER` | 仅访问分配给自己的候选人和面试，填写评价、人工接管 |
| `AUDITOR` | 只读访问授权范围内的审计、AI 运行元数据和引用 |
| 候选人 | 使用短期签名令牌访问指定问卷、预约或面试会话 |

### 1.3 第一阶段范围

`TARGET` 包含：

- 岗位、JD 版本、能力要求和评分规则版本；
- PDF、DOCX、TXT、PNG、JPG 简历导入、去重、解析、OCR 和结构化档案；
- 三路并行分析、Supervisor 汇总、确定性评分、置信度和四级分流；
- 人工改判、问卷、排期、通知和 AI 文字面试；
- 企业知识文档版本、发布、权限、混合检索、Rerank、引用和拒答；
- 任务进度、审计、基础统计、备份、发布和回滚。

`DECIDED` 不包含：

- 招聘网站直连抓取、实时语音/视频面试；
- SaaS 计费、跨企业自助租户管理；
- Kubernetes、高可用集群、本地大模型；
- AI 自动完成不可复核的录用或拒绝；
- 没有确认消费者的通用工作流引擎、插件市场或微服务拆分。

## 2. 功能需求

### 岗位、候选人与匹配

| ID | 需求 |
| --- | --- |
| `FR-001` | HR 创建、查看、停用岗位，并通过不可变 `job_version` 保存 JD 与要求快照。 |
| `FR-002` | 每个岗位版本关联一个可配置 `rubric_version`，保存维度、权重、分流阈值和置信度阈值。 |
| `FR-003` | HR 单个或批量导入简历；系统校验大小、扩展名、MIME、文件签名和 SHA-256，并异步处理。 |
| `FR-004` | 同一组织、同一岗位、同一文件的重复请求返回既有资源；跨组织文件不得因去重泄露存在性。 |
| `FR-005` | 系统解析文本 PDF、DOCX、TXT；图片或无文本 PDF 走 OCR；低质量结果进入人工复核。 |
| `FR-006` | 解析结果保存结构化档案、原文定位、解析器版本和质量信息，不得补造缺失字段。 |
| `FR-007` | Matching 使用 Basic、Skill、Experience 三路分析和 Supervisor 汇总，输出结构化证据、置信度和理由代码。 |
| `FR-008` | 最终分数由版本化确定性规则计算；AI 负责证据提取，不得私自改变权重或阈值。 |
| `FR-009` | 依据当前基线 80/60/40 分流到 `INTERVIEW`、`QUESTIONNAIRE`、`TALENT_POOL`、`CLOSED`；低置信度转 `NEEDS_REVIEW`。 |
| `FR-010` | HR 的重跑、改判、关闭、录用和拒绝操作记录前后值、原因、操作者、证据和时间。 |

### 问卷、排期与通知

| ID | 需求 |
| --- | --- |
| `FR-011` | HR 创建和版本化问卷，题目支持单选、多选、文本和可验证评分规则。 |
| `FR-012` | 系统生成一次性候选人邀请，记录有效期、使用状态和关联候选人，不在日志中记录完整令牌。 |
| `FR-013` | 候选人提交问卷后生成不可变提交版本；重复提交按业务规则拒绝或显式创建新版本。 |
| `FR-014` | HR/候选人预约可用时间段；数据库约束保证同一资源和时间段不被重复占用，冲突返回 `409`。 |
| `FR-015` | 邮件、站内通知和日历操作通过 Provider Adapter 与发送账本执行；重试不得重复产生外部副作用。 |

### AI 文字面试

| ID | 需求 |
| --- | --- |
| `FR-016` | HR 基于候选人、岗位版本和题目计划创建面试会话并发送短期签名邀请。 |
| `FR-017` | 候选人文字消息先持久化，再调用 Interview Graph；服务端通过 SSE 返回可恢复事件。 |
| `FR-018` | 面试 Graph 跟踪能力覆盖、已问问题、轮次、风险标记和退出原因，禁止询问配置中禁用的敏感属性。 |
| `FR-019` | 会话支持暂停、恢复、结束和面试官人工接管；接管后 AI 不得继续自动发言。 |
| `FR-020` | 完成后生成带原消息引用的结构化报告，面试官审核后才能进入招聘决策材料。 |

### 知识库与 RAG

| ID | 需求 |
| --- | --- |
| `FR-021` | 管理员上传知识文档并创建不可变版本，保存哈希、来源、角色范围和生命周期状态。 |
| `FR-022` | 文档经历校验、解析/OCR、质量检查、父子分块、Embedding、稀疏索引和索引提交；每步可追踪。 |
| `FR-023` | 只有显式发布且索引提交成功的当前版本可检索；草稿、处理中、失败、撤回和被替代版本不可检索。 |
| `FR-024` | 支持新增版本、重建、撤回和受控删除；发布新版本时旧版本原子切换为 `SUPERSEDED`。 |
| `FR-025` | 组织、角色和文档授权必须在候选 Chunk 查询与模型输入前生效。 |
| `FR-026` | 查询链采用 Query Normalization、Dense 检索、BM25、RRF 融合、去重、Rerank 和上下文组装。 |
| `FR-027` | 生成模型只根据允许的上下文回答，返回文档、版本、章节、页码或段落、摘录和分数引用。 |
| `FR-028` | 证据不足、矛盾或 Provider 不可用时返回明确拒答/降级状态，不使用常识补写企业制度。 |
| `FR-029` | 文档内容视为不可信数据；其中的指令不得改变系统策略、授权范围、工具白名单或泄露秘密。 |

### 平台治理与发布

| ID | 需求 |
| --- | --- |
| `FR-030` | 生产环境使用真实登录、服务端会话或短期访问令牌、RBAC 和资源级授权，不信任客户端角色请求头。 |
| `FR-031` | 对查看、下载、导出、评分、改判、发布、发送、配置变更和管理员操作写入脱敏审计。 |
| `FR-032` | 业务事务与 `outbox_events` 同库提交；发布器送达 RabbitMQ；消费者使用幂等账本、重试和 DLQ。 |
| `FR-033` | 任务记录尝试次数、租约、错误分类、下次重试时间和人工重放；数据库是任务最终事实源。 |
| `FR-034` | 仪表盘只展示事实库可计算数据，并能按组织和授权范围统计流程、耗时、失败和 AI 质量。 |
| `FR-035` | 本地验证后构建版本化 `linux/amd64` 镜像，生成摘要并传到 Linux；服务器校验、导入、迁移、启动、健康检查并可回滚。 |

## 3. 非功能需求

| ID | 要求 |
| --- | --- |
| `NFR-001` | 安全：默认拒绝、最小权限、HTTPS、SSH 密钥、内部数据库与队列不暴露公网。 |
| `NFR-002` | 隐私：PII 字段受控存储和展示，日志、事件、异常及模型元数据默认脱敏。 |
| `NFR-003` | 可追踪：请求、任务、消息、模型运行、Prompt、规则、知识版本和人工决定可关联。 |
| `NFR-004` | 可靠性：至少一次消息传递下保持业务幂等；进程重启后可恢复未完成任务。 |
| `NFR-005` | 一致性：MySQL 是业务事实源；缓存、SSE 和向量索引不得覆盖事实状态。 |
| `NFR-006` | 性能：上传和长耗时 AI 操作异步返回；具体吞吐和延迟目标在 `PD-008` 确认后冻结。 |
| `NFR-007` | 资源：`lite` 必须能在目标 2 vCPU/2 GiB 服务器受限运行，任何超限结果不得包装为 SLA。 |
| `NFR-008` | 可维护：模块化单体、单向依赖、版本化契约和 Alembic 迁移；禁止运行时自动改生产表结构。 |
| `NFR-009` | 可访问：中文管理台支持键盘操作、可见焦点、表单标签、错误说明和基本 WCAG 2.1 AA 对比度。 |
| `NFR-010` | 可恢复：发布前备份，保留上一版本镜像；数据库迁移必须说明前向修复或恢复策略。 |

## 4. UI 与交互要求

- `DECIDED` 第一阶段界面语言为简体中文；内部枚举保持英文稳定标识。
- `TARGET` 管理台是密集、安静、便于扫描的企业工具，不采用营销落地页。
- 每个异步页面具备空、加载、处理中、成功、失败、需要人工复核和无权限状态。
- 危险操作显示影响范围并要求确认；录用、拒绝、撤回知识版本等操作要求填写原因。
- SSE 断线时显示重连状态；重连失败可退回任务详情轮询，不重复创建任务。
- 候选人链接页面只暴露完成当前问卷/预约/面试所需的最少信息。

## 5. 验收标准

| ID | 场景与触发 | 可观察结果 | 禁止副作用 | 验证与优先级 |
| --- | --- | --- | --- | --- |
| `AC-001` | HR 上传支持格式简历 | `202` 返回候选人与任务 ID，任务异步推进 | HTTP 请求中执行 OCR/模型分析 | 集成测试，P0 |
| `AC-002` | 重复提交同组织、岗位、文件和幂等键 | 返回同一业务结果 | 新建重复候选人或跨组织泄露 | 集成/并发测试，P0 |
| `AC-003` | 图片或扫描 PDF OCR 失败/低置信 | 任务进入重试或 `NEEDS_REVIEW` | 生成正常匹配分或补造经历 | 故障注入，P0 |
| `AC-004` | 完成三路匹配 | 保存各维度分数、置信度、证据、理由和规则版本 | 只保存不可解释总分 | AI 评估与契约测试，P0 |
| `AC-005` | 输入 80、60、40 及相邻边界分 | 进入规定流程并产生审计 | 绕过规则版本或人工复核 | 单元/集成测试，P0 |
| `AC-006` | HR 改写 AI 分流或最终决定 | 保存前后值、原因和操作者 | 覆盖原记录或让 AI 冒充人 | 集成/审计测试，P0 |
| `AC-007` | 同一通知因超时被重试 | Provider 最多产生一次业务发送 | 重复邮件、短信或日历事件 | Provider 合同测试，P0 |
| `AC-008` | 两个请求同时预约同一资源时段 | 一个成功，另一个 `409 CONFLICT` | 出现双重预约 | MySQL 并发测试，P0 |
| `AC-009` | 面试 SSE 断线后携带 `Last-Event-ID` 重连 | 仅补发后续事件，会话继续 | 丢消息、重复 AI 发言 | E2E，P1 |
| `AC-010` | 面试官执行人工接管 | 状态为 `TAKEN_OVER`，后续 AI 输出停止 | AI 与人工同时发言 | 并发/E2E，P0 |
| `AC-011` | 管理员上传但未发布知识版本 | 查询不可检索该内容 | 草稿进入模型上下文 | 集成测试，P0 |
| `AC-012` | 查询已发布且有充分证据的制度 | 回答附可定位引用 | 引用未授权或旧版本 | RAG 评估，P0 |
| `AC-013` | 无证据、证据冲突或低于阈值 | 返回 `NO_RELIABLE_EVIDENCE` 或冲突状态 | 依据常识编写公司制度 | RAG 评估，P0 |
| `AC-014` | 无权限角色查询受限文档 | 检索候选为空，模型输入无该内容 | 先检索/生成再隐藏答案 | 权限负向测试，P0 |
| `AC-015` | 发布新知识版本 | 新版本可检索，旧版本立即排除 | 同一文档两个生产版本并存 | 事务/并发测试，P0 |
| `AC-016` | 文档写入“忽略规则/泄露密钥”等指令 | 仅作为证据文本，不改变系统行为 | 调用未授权工具或输出秘密 | Prompt Injection 测试，P0 |
| `AC-017` | 模型、Embedding、Rerank 或 OCR 超时 | 按错误类别重试、降级或人工复核 | 返回硬编码成功结果 | 故障注入，P0 |
| `AC-018` | 未授权用户访问候选人、下载文件或改判 | `401/403` 且记录安全事件 | 返回任何受保护内容 | 安全测试，P0 |
| `AC-019` | 发布包上传服务器 | `SHA256SUMS` 全部通过后才导入和启动 | 摘要失败仍继续部署 | 发布演练，P0 |
| `AC-020` | 新版本健康或 Smoke Test 失败 | 恢复上一镜像与应用配置并验证 | 删除当前/上一版本或声称撤销已发通知 | 回滚演练，P0 |

## 6. 未知项与指标约束

待决策项见 [00-index.md](00-index.md#7-待确认事项)。在这些项确认前，相关生产开关保持关闭。

`INFERENCE` 用户材料中出现的 OCR 96%+、意图识别 94%、Top-2 召回率 91%、单次分析 5 秒内、HR 工作量下降 70% 等数字可用作候选评估目标，但目前没有数据集、基线、统计周期和可复现实验日志。因此它们不是当前能力，也不是已承诺 SLA；只有在 [06-verification-release.md](06-verification-release.md) 的评估方法下取得证据后才能对外表述。
