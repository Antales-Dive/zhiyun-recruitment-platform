## 2. 项目结果

`TARGET` 建设面向单个企业组织的智能招聘平台，覆盖岗位、候选人、简历解析、可解释匹配、人才分流、问卷、面试排期、通知、AI 文字面试、知识库 RAG、审计和运营统计。

AI 的定位是提取、检索、辅助判断和流程自动化。`DECIDED` 录用、拒绝、人工改判等不可逆或高影响决定必须由有权限的人确认，AI 不得独立完成。

## 6. 全局约束

- `DECIDED` 企业级表示身份、审计、可靠性、隐私、迁移、恢复和运维责任完整，不等于盲目增加分布式组件。
- `DECIDED` 所有业务事实写入 MySQL；Redis 和向量索引可重建，不作为最终事实来源。
- `DECIDED` 组织和角色权限必须在数据库查询层生效，不能只依赖前端隐藏。
- `DECIDED` 任何模型输出必须经过结构化校验；失败是显式状态，不能用演示结果替代。
- `DECIDED` Prompt、模型配置、评分规则和知识版本均可追踪版本。
- `DECIDED` 文件、日志、事件和模型调用不得无控制地复制完整简历、联系方式和制度敏感内容。
- `DECIDED` 当前单机部署不宣称高可用；服务器故障会中断服务。
- `DECIDED` 生产发布必须保留当前版本与上一版本镜像及对应部署清单。

## 8. 主要风险

| 风险 | 影响 | 控制 |
| --- | --- | --- |
| 2 GiB 内存同时运行六个容器 | OOM、任务延迟 | 单 Worker、并发 1、资源限制、外部 AI、容量测试 |
| 当前代码自动建表 | 无法安全升级或回滚 | `TASK-001` 首先引入 Alembic |
| 请求头身份可伪造 | 越权和数据泄露 | `TASK-002` 在任何生产功能前完成 |
| 数据库轮询代替 MQ | 丢失重试语义、浪费资源 | `TASK-003` 引入 Outbox 和 RabbitMQ 消费 |
| AI 与检索质量未经评估 | 错误推荐或制度幻觉 | 固定评估集、引用约束、人工复核 |
| 外部通知不可回滚 | 重复或错误通知 | 幂等键、发送账本、人工补偿 |
| 3 Mbps 镜像传输慢 | 发布窗口过长 | 压缩、摘要校验、可续传工具、保留上一版本 |

## 9. 主实施简报

实施模型必须：

1. 只按 [05-implementation-plan.md](05-implementation-plan.md) 的任务顺序执行。
2. 每个任务开始前读取对应需求、架构和契约。
3. 只修改任务列出的文件或为同一职责新增的紧邻文件。
4. 先写能复现行为的测试，再实现；运行该任务的全部检查。
5. 检查失败时保留失败证据并停止进入下一任务。
6. 不把 Fake Provider、硬编码答案、随机分数或样例 JSON 作为生产结果。
7. 不把源码上传到服务器；发布只能使用已构建镜像和部署包。

## 10. 最终判定与生产阻塞项

判定为 `IMPLEMENTABLE`：技术路径、责任边界、契约、任务顺序和验证方式均可执行。

生产阻塞项：

- 完成 `TASK-001` 至 `TASK-003` 的迁移、身份审计和可靠任务底座；
- 确认 `PD-001` 至 `PD-006` 中与将启用功能有关的政策和 Provider；
- 移除生产路径中的演示模型返回；
- 完成 PII 保护、权限负向测试、备份恢复及上一版本回滚演练；
- 在目标 Linux 服务器上通过资源、健康检查和 Smoke Test。
